# Phase 4: the ten suggested improvements

- **Status:** done (2026-10-18); see CHANGELOG CH-023 to CH-032 for what was verified and what the owner should check
- **Roadmap items:** R4.5, R6.1–R6.8, R4.4 (macOS/Linux BLE)
- **Areas:** firmware, app, CI
- **Branch:** `phase4` (not pushed; the owner reviews it first)

## Context

After Phase 3 the owner tested the Command Center ("working so much better") and asked for every
suggested improvement, done in order, one after the other, for review the next day (2026-10-18).
Nobody can be asked during the work, so each item takes the conservative choice and records it in
`DECISIONS.md`.

**Ground rules:**
- Never risk the data on the device. The partition table stays, and NVS keeps its layout or is
  migrated.
- Every firmware step is built, flashed and run through `cc_cli.py selftest`.
- Anything that cannot be tested here (macOS, Linux, the owner's WiFi password) is said so in
  CHANGELOG.

## Items, in order

### 1. R4.5: remove the WiFi portal
- **Firmware:**
  - delete `server.c` and `spiffs.c`, the SPIFFS image and the AP mode;
  - `wifi_handles.c` becomes a station: it joins the stored network and retries 5 times at once,
    then every 30 s;
  - `wifi.set` joins without a restart; new `wifi.forget`;
  - `wifi.status` reports `not_set` instead of `ap`.
  - The partition table is unchanged: `www_0` becomes unused, and NVS is untouched.
- **Web:**
  - remove the Settings page, the HTTP fallback and the `deploy-to-firmware` script;
  - the WiFi page gets Forget.
- **App:** BLE opens the service in shared mode (the app and `cc_cli` at the same time).
- **Firmware version:** 0.7.0.

### 2. R6.1: firmware update from the app
The `ota_0` and `ota_1` partitions already exist. Protocol `fw.begin` / `fw.chunk` / `fw.end` /
`fw.abort` over BLE or USB, and an Update page in the app.

### 3. R6.2: new keymap editor
A Command Center page in the style of the others: a 4x4 grid plus 2 knobs, key search by name,
drag a key onto a slot.

### 4. R6.3: per-application layers
The Rust side watches the foreground window (Windows). Rules map an executable to a layer and send
`layers.set_active`.

### 5. R6.4: tray and autostart
A tray icon with the active layer; closing the window hides it to the tray; start with Windows;
a notice when the link is lost.

### 6. R6.5: battery, sleep, OLED dimming
`device.settings.get/set`: sleep minutes and OLED brightness/timeout. Battery level in
`device.info` when the hardware reports one.

### 7. R6.6: CI
GitHub Actions:
- firmware in `espressif/idf:v4.4.7`;
- the Angular build;
- the Windows installer;
- a release with the installer and the firmware `.bin` on tags `v*`.

### 8. R4.4: macOS and Linux BLE
A btleplug backend for non-Windows behind the same `link.rs` interface. Compile-checked in CI;
not testable on hardware here.

### 9. R6.7: tap-dance / mod-tap, richer macros
Firmware, protocol and UI.

### 10. R6.8: share single layers
Export and import one layer, with its key colours, as a file.

## Verification

Per item: build, flash, `cc_cli.py --usb COM3 --ble selftest` (0 failures), heap via
`device.info`, the app self-test, and the pages driven through the WebView2 DevTools port.
